# Muverse: YouTube search + player (ชุดทดสอบฟีเจอร์ ไม่มีดีไซน์)

## วิธีรัน (VS Code)

1. ติดตั้ง [Node.js](https://nodejs.org) เวอร์ชัน 18.18 ขึ้นไป (แนะนำ 20 LTS)
2. เปิดโฟลเดอร์ `muverse` ด้วย VS Code (File > Open Folder)
3. ใส่คีย์ในไฟล์ `.env.local` ให้เป็น `YOUTUBE_API_KEY=คีย์ของคุณ`
4. เปิด Terminal ใน VS Code (Ctrl+`) แล้วรัน:

```
npm install
npm run dev
```

5. เปิด http://localhost:3100

โปรเจกต์นี้ใช้พอร์ต **3100** เพื่อไม่ชนกับโปรเจกต์เดิมที่ใช้พอร์ต 3000

หลังแก้ `.env.local` ต้องหยุดแล้วรัน `npm run dev` ใหม่

## ขอ YouTube API key

1. เข้า Google Cloud Console แล้วสร้างโปรเจกต์
2. เปิดใช้ **YouTube Data API v3**
3. สร้าง API key (จำกัดให้ใช้ได้เฉพาะ YouTube Data API v3)

อย่า commit `.env.local` ขึ้น Git (ถูกใส่ใน `.gitignore` แล้ว)

## โครงสร้าง

```
app/
  page.tsx                              หน้าเดียวที่ "/" (ค้นหา + เล่น)
  layout.tsx, globals.css
  api/youtube/search/route.ts           ค้นหาผ่าน YouTube Data API (ฝั่งเซิร์ฟเวอร์)
components/
  youtube-player.tsx / .css             เครื่องเล่น (IFrame API + ตัวควบคุมเอง)
  youtube-search.tsx                    ช่องค้นหา + ผลลัพธ์
lib/youtube.ts                          ชนิดข้อมูล + ตัวโหลด IFrame API
```

## ประวัติการเข้าชม

เปิดส่วน “ประวัติการเข้าชม” เพื่อดูคลิปที่เคยเปิด โดยเรียงล่าสุดก่อนและเก็บสูงสุด 100 คลิป เปิดซ้ำจะเลื่อนขึ้นด้านบนแทนการเพิ่มซ้ำ กดเปิดดูอีกครั้ง ลบทีละรายการ หรือล้างทั้งหมดได้ การรีเฟรชไม่สร้างรายการที่ลบกลับมาเอง

ประวัติเก็บในเบราว์เซอร์ของเครื่องนั้น ไม่ซิงก์ระหว่างเครื่องหรือบัญชี หากเบราว์เซอร์ปิดกั้นการบันทึก จะแสดงข้อความและใช้ประวัติชั่วคราวเฉพาะหน้านั้น ประวัตินับการเปิดคลิป ไม่ได้ยืนยันว่าดูจบ

## ไฮไลท์ท่อนฮุคอัตโนมัติ

ใช้ระบบเดียวกันทุกคลิป ไม่มีรายการเวลาเฉพาะเพลงหรือ video ID:

1. อ่าน chapter ที่ผู้อัปโหลดระบุว่าเป็น chorus/hook หรือ dance break แยกประเภทกัน (ไม่รวม pre-chorus/post-chorus)
2. อ่านรายการแบ่งท่อนและช่วงเวลาเริ่ม–จบในคอมเมนต์ รองรับทั้ง `1:59–2:34 Dance Break` และ `Dance Break 1:59–2:34` โดยแสดงแหล่งข้อมูล ถ้าเป็นช่วงที่ไม่ได้ติดป้าย ต้องมีคอมเมนต์ระบุ dance break ใกล้จุดเริ่มและมีไทม์สแตมป์สนับสนุนอย่างน้อยสามข้อความต่างกัน ไม่สร้างจุดจบขึ้นเอง
3. ค้นหาเนื้อเพลงแบบมีเวลากำกับจาก LRCLIB แล้วหาท่อนซ้ำ รวมคำสั้นในฮุคด้วย ใช้ชื่อเพลงช่วยแยกฮุคออกจาก pre-chorus ที่ซ้ำติดกัน ไม่ตัดท่อนด้วยเพดาน 40 วินาทีแบบเดิม หากบล็อกซ้ำยาวเกิน 60 วินาทีจะงดเสนอแทนการตัดมาครึ่งท่อน จากนั้นรวมกับเบรคแดนซ์ที่มีข้อมูลขอบเขตแยกกัน โดยไม่ให้ผลสองแหล่งซ้อนทับกัน
4. หากความยาวคลิปกับเพลงต่างกัน ต้องมีไทม์สแตมป์ฮุค หรือข้อความอ้างเนื้อร้องที่ตรงกันอย่างน้อยสองตำแหน่งเพื่อจัดเวลาอัตโนมัติ ข้อความอ้างเนื้อร้องต้องเป็นคนละบรรทัดและอยู่ห่างกันอย่างน้อย 20 วินาที หากหลักฐานไม่พอหรือขัดแย้งกันจะไม่แสดงไฮไลท์
5. ตรวจความสอดคล้องของความยาวเพลงกับเวลาใน LRC และคัดรายการเนื้อเพลงซ้ำที่ระบุความยาวผิดปกติออกก่อนจับคู่ ไม่เลือกจากความยาวที่ใกล้คลิปอย่างเดียว

การรองรับ T-pop: คงชื่อเพลงไทยและชื่ออังกฤษในวงเล็บไว้สำหรับคำค้นสำรอง แยกชื่อเพลงออกจากคำอธิบายหรือผู้สนับสนุน รองรับชื่อเพลงสองภาษาโดยยังตรวจชื่อศิลปิน เทียบบรรทัดไทยที่เว้นวรรคต่างกันหรือมีอักขระล่องหนได้ และใช้ไทม์สแตมป์ที่อ้างเนื้อร้องไทยยาวพอเป็นหลักฐานจัดเวลาได้ รองรับทั้ง “ฮุค”, “ฮุก” และ “ท่อนสร้อย” โดยไม่รวม “ก่อนฮุก/หลังฮุก”

ถ้าพบเฉพาะเนื้อเพลงที่ไม่มีเวลา จะตอบ `untimed-lyrics` และไม่สร้างเวลาขึ้นเอง ตัวอย่างทดสอบ API จริงในรอบนี้: PiXXiE “เกินต้าน” mirrored (`kmA5dYR22zo`) พบสองช่วงที่ระบบคาดการณ์เป็นฮุค ส่วน 4EVE “Vroom Vroom” (`Qnfpvp6rL-I`) พบเฉพาะเนื้อเพลงที่ไม่มีเวลา และ BNK48 คลิปสั้น (`5Cw3j9Q6LKQ`) ยังจับคู่ไม่ได้ ทั้งสองคลิปหลังยังไม่มีไฮไลท์ ผลตัวอย่างไม่ได้ยืนยันขอบเขตด้วยการฟังเสียง

ผู้ใช้สามารถกดเล่นและวนซ้ำไฮไลท์ที่ระบบตรวจพบได้ ไม่มีการเพิ่ม/แก้ช่วงเองหรือปรับเวลาเอง และไม่อ่านรายการช่วงหรือค่าเวลาที่เคยบันทึกไว้ในเบราว์เซอร์

ข้อจำกัด: YouTube Data API และ IFrame API ไม่ส่งเสียง/เฟรมสำหรับวิเคราะห์ ระบบนี้ไม่ได้ตรวจเสียงหรือท่าเต้นซ้ำ และไม่รับประกันฮุคอัตโนมัติครบทุกคลิป เนื้อเพลงหรือคอมเมนต์อาจผิด ส่วนคลิปตัดต่อ เปลี่ยนความเร็ว เพลงที่ไม่มีเนื้อร้อง หรือเพลงที่ไม่พบในฐานข้อมูล อาจไม่มีไฮไลท์ การเลื่อนเวลาคงที่ไม่แก้คลิปที่ตัดต่อหลายจุด

ตัวอย่างทดสอบจริง: BAD mirrored (`3ZO5F5wUmBg`) มีข้อมูลสนับสนุนช่วงเบรคแดนซ์ 1:59–2:34 โดยผู้ใช้ยืนยันเฉพาะจุดเริ่ม 1:59 ส่วน PSYCHO Practice (`AydyGsqLvXs`) ที่ผู้ใช้ยืนยันเบรคแดนซ์เริ่ม 2:40 ยังไม่มีข้อมูลขอบเขตเพียงพอ ระบบจึงยังไม่แสดงช่วงนั้น ตัวอย่างอยู่ใน `tests/fixtures/highlight-reference-cases.json` ไม่ได้ใช้เป็นข้อยกเว้นใน production

ทดสอบด้วย Node.js 24: `node --test tests/*.test.mjs` และตรวจ build ด้วย `npm run build`
ในสภาพแวดล้อม cloud ที่ต้องใช้พร็อกซี ให้เริ่มด้วย `NODE_USE_ENV_PROXY=1 npm run dev`

## โควตา API

โควตาเริ่มต้น 10,000 หน่วยต่อวัน การค้นหาหนึ่งครั้งใช้ราว 101 หน่วย (ประมาณ 99 ครั้งต่อวัน)
ผลลัพธ์ถูกแคชฝั่งเซิร์ฟเวอร์ 1 ชั่วโมง คำค้นเดิมจึงไม่กินโควตาซ้ำ

## ถ้าเจอปัญหา

- ขึ้น "ยังไม่ได้ตั้งค่า YOUTUBE_API_KEY": ยังไม่ได้ใส่คีย์ หรือยังไม่ได้รัน dev ใหม่หลังใส่
- ขึ้นข้อความ API key not valid / quota: ตรวจว่าเปิด YouTube Data API v3 แล้ว และโควตายังไม่หมด
- คลิปเล่นไม่ได้: เจ้าของคลิปปิดการฝัง ให้เลือกคลิปอื่น

# Muverse

Muverse คือเว็บสำหรับค้นหาและฝึกเต้นตามวิดีโอจาก YouTube มีระบบเสนอช่วงไฮไลท์ วิเคราะห์ตำแหน่งและฟอร์เมชันของนักเต้น และจัดเก็บเพลย์ลิสต์กับการแก้ไขไว้ในเบราว์เซอร์

## ความสามารถหลัก

- **ค้นหาและเล่นวิดีโอ** — ค้นหาวิดีโอเต้นผ่าน YouTube Data API และเล่นด้วย YouTube IFrame Player
- **ไฮไลท์และท่อน A–B** — รวมข้อมูลบทของวิดีโอ ความเห็นที่ระบุช่วงชัดเจน ข้อมูลเนื้อเพลงแบบมีเวลา และการวิเคราะห์เสียง เพื่อเสนอช่วงที่อาจเป็นท่อนฮุค ผู้ใช้เลือก แก้ไข และบันทึกช่วงได้ ผลเป็นเพียงข้อเสนอและอาจไม่พบหรือคลาดเคลื่อน
- **วิเคราะห์ฟอร์เมชัน** — worker ภาษา Python ใช้ YOLO26s-pose ตรวจจับท่าทางและประมาณตำแหน่งบนพื้นเวที หลังผู้ใช้กำหนดมุมเวที 4 จุดแล้ว เว็บจะแสดงไทม์ไลน์ที่แก้ไขจุดและชื่อได้
- **Random Dance** — สุ่มเล่นคลิปที่มีทั้งไฮไลท์และฟอร์เมชันที่วิเคราะห์และบันทึกแล้ว
- **เพลย์ลิสต์และประวัติ** — จัดการรายการคลิป สลับลำดับ ถูกใจ และดูประวัติการรับชม
- **โหมดเต็มจอ** — ดูวิดีโอและเปิดแผงเครื่องมือฝึกจากหน้าจอเต็มได้

หน้า Random Dance มีเพลย์ลิสต์แนะนำ 3 ชุด ได้แก่ Trending, T-pop และ K-pop Mix ชุดละ 6 คลิป พร้อมข้อมูลไฮไลท์และฟอร์เมชันที่เตรียมไว้สำหรับ 14 คลิปไม่ซ้ำ ข้อมูลตั้งต้นอยู่ใน `data/recommended-playlists.json` แยกจากเพลย์ลิสต์ส่วนตัว จึงแสดงให้ผู้ใช้ใหม่ได้โดยไม่ปะปนกับเพลย์ลิสต์ส่วนตัว

การตรวจจับภาพอาจนับนักเต้นหรือตำแหน่งคลาดเคลื่อนเมื่อถูกบัง อยู่นอกเฟรม หรือภาพไม่ชัด จึงแก้ผลจากแผนผังได้ก่อนนำไปใช้

## เริ่มเว็บ

ต้องมี Node.js 20 LTS และคีย์ YouTube Data API v3 จาก [Google Cloud Console](https://console.cloud.google.com/) ให้เปิด API และจำกัดคีย์ให้ใช้กับ YouTube Data API v3 จากนั้นสร้าง `.env.local` ที่โฟลเดอร์หลัก:

```dotenv
YOUTUBE_API_KEY=ใส่คีย์ของคุณ
AUDIO_ANALYSIS_URL=http://127.0.0.1:8765
```

ติดตั้งแพ็กเกจและเปิดเว็บ:

```powershell
npm ci
npm run dev
```

เปิด <http://localhost:3100> คำสั่ง `npm run build` ใช้สร้างรุ่นสำหรับ production ส่วน `npm start` ใช้เปิดรุ่นที่ build แล้ว รายละเอียดการตั้งค่า worker และการวิเคราะห์อยู่ใน [คู่มือติดตั้งและส่งต่องาน](docs/DEVELOPER_GUIDE.md)

## การวิเคราะห์ด้วย worker

การค้นหาและเล่นวิดีโอต้องตั้ง `YOUTUBE_API_KEY` และขึ้นอยู่กับบริการของ YouTube การวิเคราะห์เสียงและฟอร์เมชันใหม่ต้องเปิด worker ใน `services/audio-analysis` แยกจากเว็บ Worker ทำงานบน `127.0.0.1:8765` เป็นค่าเริ่มต้น และใช้ FFmpeg; การวิเคราะห์ฟอร์เมชันต้องติดตั้งแพ็กเกจ YOLO เพิ่ม

การวิเคราะห์เสียงโหมด `fast` เสนอช่วงเสียงที่มีรูปแบบซ้ำ ไม่ได้ยืนยันว่าช่วงนั้นเป็นท่อนฮุค ส่วนการวิเคราะห์ฟอร์เมชันอาจพลาดตำแหน่งบางคน ควรตรวจและแก้ผลก่อนบันทึก อ่าน [คู่มือ worker](services/audio-analysis/README.md) สำหรับข้อกำหนดและตัวแปรตั้งค่า

## ข้อมูลและความเป็นส่วนตัว

เพลย์ลิสต์ การกดถูกใจ ประวัติ ไฮไลท์ ฟอร์เมชัน ชื่อที่แก้ และมุมเวที เก็บใน `localStorage` ของเบราว์เซอร์นั้น จึงไม่ซิงก์ไปยังเบราว์เซอร์หรือคอมพิวเตอร์อื่น การล้างข้อมูลเว็บไซต์อาจลบข้อมูลเหล่านี้

Worker ผูกพอร์ตกับ loopback เพื่อใช้งานในเครื่องเดียว ไฟล์สื่อที่ใช้วิเคราะห์เป็นไฟล์ชั่วคราวและลบเมื่อจบงาน อย่าเปิด worker สู่เครือข่ายสาธารณะโดยตรง และห้าม commit `.env.local`, API key หรือ token

## โครงสร้างสำคัญ

- `app/` — หน้าเว็บและ API routes
- `components/` — เครื่องเล่น เพลย์ลิสต์ และส่วนติดต่อผู้ใช้
- `lib/` — การจัดการสถานะและผลวิเคราะห์ในเบราว์เซอร์
- `services/audio-analysis/` — worker และสคริปต์วิเคราะห์เสียง/ฟอร์เมชัน
- `docs/` — คู่มือนักพัฒนาและบันทึกการผสานแนวทาง UI
- `tests/fixtures/` — ข้อมูลอ้างอิงสำหรับทดสอบอัลกอริทึม ไม่ใช่กฎกำหนดเวลาในระบบจริง

## ซอฟต์แวร์และสิทธิ์ใช้งาน

- [Next.js](https://github.com/vercel/next.js), [React](https://github.com/facebook/react) — เว็บแอป
- [Ultralytics](https://github.com/ultralytics/ultralytics) — runtime และโมเดลตรวจจับท่าทาง โปรดตรวจสิทธิ์ใช้งาน AGPL-3.0 หรือ Enterprise ก่อนเผยแพร่หรือให้บริการ
- [yt-dlp](https://github.com/yt-dlp/yt-dlp), [FFmpeg](https://ffmpeg.org/) — ดาวน์โหลดชั่วคราวและถอดรหัสสื่อสำหรับ worker
- [LRCLIB](https://lrclib.net/) — ข้อมูลเนื้อเพลงที่มีเวลาเพื่อช่วยจัดแนวไฮไลท์
- แนวคิดการกำหนดขอบพื้นเวทีอ้างอิง workflow ของ [GridStage](https://github.com/ChangShengHsun/GridStage) แต่โค้ดของ Muverse เป็นการพัฒนาแยก

ตรวจเงื่อนไขของบริการและไลบรารีที่ใช้ก่อนนำไปเผยแพร่หรือใช้งานเชิงพาณิชย์
